# Theme v2 Phase 2–4 — Independent Audit Report

_Status: **complete**. The schema/loader engine and the shipped v2 themes meet the spec. The Phase 3 renderer did not: its animation layer was a skeleton that could not satisfy §4.9. That layer has been implemented, and the Phase 4 render gate has been replaced with a real old-vs-new oracle._

---

## 1. Method

The audit verified claims against the spec (`docs/theme_schema_v2.md`) and against the running renderer, in this order:

1. Read the Phase 2–4 reports and the normative spec.
2. Ran the schema, migration, security, shared, position, animation, and designer round-trip suites.
3. Drove the real renderer in headless Chrome and compared it with the **pre-v2 renderer at `5f9acd8`**, not with fixtures generated by the new code.
4. Fixed behavior only where the evidence showed a spec violation or a regression.
5. Re-ran the affected suites; no test was weakened, skipped, or deleted.

No commits, stashes, or resets were made. The two earlier agent commits (`1597593`, `d85784c`) stand.

## 3. Phase 2 — schema, migration, loader

No defects required a fix. Spot checks confirmed the load-bearing contracts:

- `get_theme()` returns the **raw** on-disk dict (designer path); `resolve_theme(name, fallback)` returns `(name, deepcopy)` of the migrated, validated, default-filled v2 theme (render path).
- `save_theme()` performs no normalization, so unknown/v2 fields survive a load-edit-save round trip. Validation repairs go to `ThemeReport.note()` and do not rewrite user files.
- V1 themes are migrated in memory only. Nothing writes a migrated dict back to disk on load.
- `themes/_shared/` is skipped by `_is_theme_path` and is never listed as a theme type or theme.
- `schema_version > 2` and invalid themes fall back to `SAFE_THEME`; enums/ranges clamp; CSS/HTML injection is rejected or escaped.

Test evidence: `test_theme_v2_schema.py` 35, `test_theme_v2_migration.py` 44, `test_theme_v2_security.py` 118, `test_theme_v2_shared.py` 56 — all pass.

## 4. Phase 3 — renderer

### 4.1 Defects found in the delivered renderer

The Phase 3 report claimed the animation engine was complete. At `d85784c` it was not:

- `_runAnimation(data, phase)` used the **legacy v1 phase names** (`display_enter` / `between_slides`) and read `data.theme_data` instead of the resolved theme. `handlePayload` called it after the swap on **every** payload where `_prevPayload` existed — no content diff, so a same-verse theme restyle replayed the transition.
- There was **no `_playTypewriter`**, no `transition.out` collection, no per-block `out`, no `prefers-reduced-motion` handling, and no coalescing of rapid updates.
- `_runExitAnimation` read only the first container and used a legacy `display_exit` CSS class path that v2 themes never populate.
- A block-level outline was never checked before running the typewriter, because the typewriter did not exist.

These were not documentation gaps; the spec's §4.9 behavior was unreachable.

### 4.2 Fixes applied

| Area | Fix |
|------|-----|
| Phase selection | `_renderDisplay(data, silent, changed, phase)` is now the single commit point. `handlePayload` computes `entry` (first content), `in` (content changed), or `null` (same content) from a per-block diff (`_payloadSources` / `_changedSources`). A theme-only re-broadcast is fully silent. |
| Transition | `_collectTransitionOut(theme, changed)` picks the old theme's `transition.out` targets whose block content changed. The out phase plays **before** the swap/fit; `in` plays after, from the incoming theme. |
| Per-block out | `_collectExit(theme)` plays every changed block's `out` before the container is hidden; the callback waits for the longest phase. |
| Entry | `_runAnimation("entry", changed)` plays `entry` on every animation target. |
| Typewriter | `_playTypewriter` splits text into `[data-rc-tw]` spans using `Intl.Segmenter` graphemes (or word segments), preserves whitespace with the preceding segment, reserves layout with `visibility` (not `display`), draws an optional cursor, and unwraps back to the original text nodes. A **hard finish timer** at `delay + duration + 50 ms` guarantees completion even if `requestAnimationFrame` never fires. |
| Guards | Typewriter is text-only: `out` falls back to `fade_out`; container/body targets fall back to `fade_in`; a converted outline scope (`.rc-oc` or block `text_outline`) falls back to `fade_in` instead of re-splitting the SVG. |
| Reduced motion | `_reducedMotion()` suppresses entry/in/out/typewriter plans, and `_collectTransitionOut` returns `[]` so swaps and clears are immediate rather than waiting out an animation that never plays. |
| Coalescing | A phase token invalidates the pending out timer when a newer payload arrives; the superseded content never renders. |
| Silent resync | `refreshPayload()` / `refreshClear()` keep `_prevPayload` untouched, so a tab-switch resync does not force an entry animation on the next payload. |

The animation/payload blocks in `display/display.js` and `ui/widgets/display_view.py` are byte-identical (verified by extracting both blocks and comparing them); both pass `node --check`.

### 4.3 Preview viewport

- **Zoom:** v1 themes carry `canvas.fit: "none"` so OBS never rescales them. The in-app preview is a viewport, not the OBS surface, so `window.__RC_PREVIEW === true` forces `fit: "contain"` at runtime. OBS behavior is unchanged.
- **White background:** `DisplayView` sets `page().setBackgroundColor(QColor("#000000"))`; `display/display.html` remains transparent for OBS. The White toggle still works because `set_screen_white` uses inline `background:#ffffff !important`.
- **Vertical centering:** container/body flex ownership was corrected, and the `"none"` border is written as a real CSS value to `--rc-container-border` instead of producing an invalid declaration.

### 4.4 Runtime evidence (headless Chrome)

Driven against the real renderer, both copies:

- Entry plays on first display; a same-content re-broadcast produces **zero** animations.
- `transition.out` plays on the old text, the swap happens only after it finishes, then `in` runs on the new text.
- Typewriter creates `[data-rc-tw]` spans, reveals to completion, then restores plain text.
- Clear plays per-block `out`, then hides the container.
- A second update during the out phase cancels it; the superseded payload never reaches the DOM.
- `--force-prefers-reduced-motion` skips every phase and swaps instantly.
- A block-level outline produces no typewriter split and no console errors.

Permanent coverage: `tests/test_theme_v2_animation_runtime.py` (30 tests) plus 10 new pure-helper tests in `tests/test_display_js.py`.

### 4.5 Cloak regression (found after the first pass)

Cloak stopped blanking: the verse stayed visible, shifted down and slightly smaller. That is the *hidden transform* painting while the opacity rule lost the cascade.

- **Cause.** Resolved v2 themes fill `container.opacity: 1`, and `_applyContainers` writes it as an inline style. `themes.css` hid the container with a plain `#container.hidden { opacity: 0 }`, which an inline declaration always beats. `visibility` was never set, so the only thing that changed was `transform: translateY(40px) scale(0.98)` — exactly the small reposition seen on screen.
- **Fix.** `.hidden` is now a hard hide: `opacity: 0 !important`, `visibility: hidden`, `transform: none`, `pointer-events: none`. `out` animations still play first — the class lands only in the exit callback. Themes without an `out` hide immediately, which is the intended behavior.
- **Second bug, same path.** `_renderMultiContainers` created/reused `.rc-dynamic-container` nodes but never removed `.hidden`, so a clear made dynamic containers permanently invisible. Every render now clears the class.
- **Third bug.** `_runExitAnimation` preferred `_prevPayload.theme_data` over `_currentTheme`, so a cloak after a theme-only restyle played the *old* theme's `out`. It now reads `_currentTheme` first, matching what is actually on screen.
- **Proof.** Headless-Chrome probe (`/tmp/opencode/rc_audit/cloak_probe.py`) on a resolved shipped theme: before the fix `hidden` computed `opacity: 1`, `transform: matrix(0.98, …, 40)`, `visibility: visible`; after, `opacity: 0`, `transform: none`, `visibility: hidden`. Reverting only the CSS rule makes the two new cloak tests fail with `assert '1' == '0'` at the `containerOpacity` assertion, so the tests are not vacuous.

### 4.6 Renderer gaps exposed by the showcase themes

The eight showcase themes are deliberately built out of v2-only features, so
driving them through both renderers found contracts that validated in Python
but were dropped on screen:

- **Per-side borders.** `border.sides` is documented as per-side declarations,
  but the single-container path only wrote the base shorthand and the
  multi-container path ignored the field. `reference_frames` (1px top/bottom,
  5px left/right) rendered four equal sides. `_applyBorder()` now writes the
  base shorthand first and then overrides only authored sides; re-setting the
  shorthand also clears longhands a previous container wrote, so
  `fullscreen_split`'s citation panel shows its own 1px hairline instead of
  the verse panel's 2px gold.
- **Single-container height.** Resolved panels express their height through
  `min_height`/`max_height` while `height` stays `auto`, but only the
  `--rc-height` variable was written. `fullscreen_rise`/`_pop`/`default_typewriter`
  collapsed to their content (~360px). Both heights are now written inline.
- **`autosize` on a min_height panel.** The fit loop read only `--rc-height`,
  so `height:auto` + `min_height` (all four showcase panels) skipped fitting:
  a long verse kept its authored size and grew the auto-height panel until the
  stage clipped it — the clipped-verse the preview showed. The target is now
  the authored `min_height`/`max_height` minus the panel's padding and border,
  with a refit on the next frame and again after webfonts settle (the bundled
  Nunito lands after the first fit). Covered by
  `test_v2_min_height_panel_autosizes_long_text`.
- **Per-panel autosize in split themes.** The multi-container path never ran a
  fit at all, so every panel rendered at its authored size (a 76px verse
  measured 1067px tall inside a 780px panel and clipped on both edges). Each
  panel now fits its own text block between that block's `min_size`/`max_size`
  against its own content box, before outline conversion and again once
  webfonts settle. A block with `max_lines` caps growth at its authored size
  (a clamp reports the same height at every size, so "fits" would otherwise
  mean "grow to max"). Covered by
  `test_v2_multi_container_autosizes_each_panel`.

- **Per-unit split animations.** `animation.split` computes line or word units
  from the rendered layout on every payload, then applies per-unit `first`/
  `rest` phase assignments, looks, and `stagger_ms` delays. First-line versus
  rest is therefore a theme parameter, not a fixed effect; the first rendered
  line is always unit 0, and the count changes when wrapping changes. Covered
  by `test_v2_split_animation_is_computed_per_line_and_word` and four schema
  tests. See `docs/theme_schema_v2.md` §4.9.8.
- **Split assignment inheritance and opacity.** Two defects surfaced only when
  the split contract was driven directly. `_splitAssignment` shallow-merged
  `transition`, so a unit that overrode only `transition.out` silently lost
  the inherited `transition.in`; the phase map is now merged deeply. And
  `look.opacity` was written to both a line unit and each word inside it,
  multiplying to 0.49 instead of the authored 0.7; opacity now applies to the
  unit only, since it inherits down the DOM tree. Covered by
  `test_v2_split_assignment_merges_transition_phases` and the
  `restWordOpacity` assertion in the split runtime test.
- **Per-container block ownership.** `_getContainerBlocks()` fills every key
  with `{}`, and the multi-container renderer treated `{}` as present, so a
  citation-only panel duplicated the verse. `_authoredBlock()` reads presence
  from the raw container, so `fullscreen_split` renders one verse and one
  reference across both panels.
- **Translation typography.** The multi-container `makeRefEl()` applied only
  colour, margin and position; size, weight, family, letter-spacing,
  line-height and text-transform were ignored. All are applied now, matching
  the single-container cascade.
- **Verification.** Full 8-theme x 2-renderer probe: no JS errors; side
  borders, gradients and radii match the authored values; cloak blanks both
  paths and reopen restores them. Four focused runtime tests (parameterized
  over both renderers) plus a showcase smoke test cover these paths:
  `test_v2_reference_frames_renders_authored_border_sides`,
  `test_v2_multi_container_blocks_stay_in_their_container`,
  `test_v2_min_height_panel_is_applied`,
  `test_v2_showcase_themes_render_and_cloak`.
- **Remaining block styles.** The multi-container h1 now also applies
  `word_spacing`, `font_style`, `text_decoration`, `direction` and
  `max_lines` (Chromium line clamp), and block-level `text_outline`
  converts per panel. `_ocScale()` takes the element being converted:
  `#verse-text` is `display:none` in a split theme, so the old global
  measurement returned a zero scale and aborted the outline. Covered by
  `test_v2_multi_container_text_block_typography`.

## 5. Phase 4 — shipped themes and the render gate

### 5.1 Themes

All fourteen shipped themes (the six original themes plus eight showcase themes) are valid v2 (`schema_version: 2`, `containers` array) and resolve with zero warnings. For the six original themes, `normalize_theme(migrate_v1_to_v2(v1_fixture))` deep-equals the resolved on-disk v2 theme. The shared definitions are present and correctly namespaced.

### 5.2 The original "golden" test was not a render test

`test_golden_fixture_container_metrics_match_resolved_v2` loaded `tests/golden_fixtures_phase2.json` and compared the resolved container's `position.x/y`, `width`, and `height` fields to values derived from those same theme fields. It never started a browser, never rendered text, and could not detect a renderer regression. It was replaced, not relaxed.

### 5.3 Real oracle

`tests/golden_render_v1.json` is now captured from the **pre-v2 renderer at `5f9acd8`** running the pristine v1 fixtures at 1920×1080. The suite renders each resolved v2 theme in headless Chrome and compares:

- container box,
- text/reference/translation **glyph range** boxes,
- computed typography (size, line-height, weight, family, spacing, color, alignment, transform, style, decoration).

Glyph ranges rather than block boxes are used because v2 mandates full-width stack rows; block boxes may differ while visible text may not move.

**Font determinism:** the harness strips the Google Fonts `<link>`s and preloads the bundled Nunito faces before rendering. Network-fed Nunito has different metrics and made the comparison flaky; the oracle was captured under the same offline conditions.

**Result:** worst old-vs-new rect delta across 6 themes × short/long = **0.020 px**; all typography properties identical. The suite passes 19/19 repeatedly.

## 8. Known limitations (non-blocking)

- **Multi-container `body` animation target.** Multi-container blocks have no dedicated stack wrapper, so `_bodyElement()` returns the container element itself. A `body` animation and a container animation in the same multi-container theme therefore play on the same node rather than on distinct elements. Single-container themes (all six shipped themes) use `#verse-content` correctly.
- **Headless WAAPI clock.** Chrome's virtual time freezes WAAPI `currentTime` in DOM dumps, so runtime tests assert animation existence, target, and phase gating, not interpolated paint. Typewriter completion is additionally guaranteed by the hard finish timer, which is what makes it testable headlessly. The same freeze can leave a finished entry animation unresolved in `getAnimations()` (observed on `default_quiet`/`fullscreen_pop`, `tracked: True`), because the `finished` promise never settles while the compositor is frozen. It is a headless artifact, not a renderer leak: the filled end frame equals the resting style, and `_cancelAllAnimations()` cancels every tracked animation on the next payload or theme change.
- **Legacy `@keyframes` path.** It remains only for raw v1 payloads that bypass Python; v2 themes always use WAAPI.
